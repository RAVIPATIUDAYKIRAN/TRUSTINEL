# TRUSTINEL - Sprint 2 Database Design

This document details the database schema design for Sprint 2. The database will feature exactly three tables, with all IP address tracking fields omitted for privacy and simplicities.

---

## 🗄 Entities & Tables

### 1. `website_scans`
Stores records of website scan executions.

| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, default: `gen_random_uuid()` | Unique identifier of the scan. |
| `url` | `TEXT` | `NOT NULL` | The full parsed target URL scanned. |
| `domain` | `VARCHAR(255)` | `NOT NULL` | The extracted hostname/domain. |
| `status` | `VARCHAR(50)` | `NOT NULL` | Lifecycle state: `PENDING`, `COMPLETED`, `FAILED`. |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `NOT NULL`, default: `NOW()` | Timestamp when scan was created. |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | `NOT NULL`, default: `NOW()` | Timestamp when scan was last updated. |

- **Index recommendations**:
  - Index on `domain` (for domain lookup performance).
  - Index on `created_at` (for date ranges/historical queries).

---

### 2. `trust_reports`
Stores trust ratings generated by the scanning engine.

| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, default: `gen_random_uuid()` | Unique identifier of the report. |
| `scan_id` | `UUID` | `FOREIGN KEY` references `website_scans(id)` | Link to parent scan. Unique constraint. |
| `trust_score` | `INTEGER` | `NOT NULL`, check (`trust_score >= 0 AND trust_score <= 100`) | Calculated score (0 - 100). |
| `risk_level` | `VARCHAR(50)` | `NOT NULL` | Categorization: `SAFE`, `SUSPICIOUS`, `DANGEROUS`. |
| `summary` | `TEXT` | `NOT NULL` | A brief textual justification for the rating. |
| `generated_at` | `TIMESTAMP WITH TIME ZONE` | `NOT NULL`, default: `NOW()` | Generation timestamp. |

- **Constraints**:
  - Unique constraint on `scan_id` (ensures one report per scan - 1:1 relationship).
  - Check constraint on `trust_score` (must be between 0 and 100 inclusive).

---

### 3. `scan_history`
Tracks the chronological events and actions associated with a scan.

| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, default: `gen_random_uuid()` | Unique history event identifier. |
| `scan_id` | `UUID` | `FOREIGN KEY` references `website_scans(id)` | Reference to the scan lifecycle. |
| `action` | `VARCHAR(100)` | `NOT NULL` | Action taken: `SCAN_INITIATED`, `REPORT_GENERATED`, `SCAN_FAILED`. |
| `status` | `VARCHAR(50)` | `NOT NULL` | Status state of the action. |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `NOT NULL`, default: `NOW()` | Action creation timestamp. |

- **Index recommendations**:
  - Index on `scan_id` (to speed up joins and fetching event logs for a given scan).

---

## 🔄 Relationships
1. **`website_scans` ↔ `trust_reports`**: One-to-One (`1:1`). A scan record may have zero (if pending/failed) or exactly one completed trust report.
2. **`website_scans` ↔ `scan_history`**: One-to-Many (`1:N`). A scan record has one or more chronological history items tracking states.
